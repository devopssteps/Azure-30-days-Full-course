# **Azure Functions Hands-On: Automatically Process Uploaded Files**

Python

Azure Blob Storage Trigger

In this demo we will understand three important Azure services working together:

- **Azure Storage Account:** Stores uploaded files.
- **Azure Function:** Automatically executes Python code when a file is uploaded.
- **Azure Storage Account (destination):** Stores the file information generated by the function.

## **1. What are we going to build?**

Imagine that a user uploads a PDF, JPG, PNG, or TXT file to Azure Storage.

As soon as the file is uploaded, an Azure Function automatically triggers and collects:

1. File name
2. File extension/type
3. File size
4. MIME/content type
5. Upload timestamp

The function then creates a JSON file containing this information and uploads that JSON file into another Azure Storage container.


### **Architecture of our project**

**Step 1: User uploads a file**

PDF / JPG / PNG / TXT

**Step 2: Source Azure Storage**

uploads container

Stores the original uploaded file

Blob Trigger automatically fires

**Step 3: Azure Function**

Executes Python code and extracts file metadata

**Step 4: Destination Azure Storage**

file-metadata container

Stores generated JSON files

We are not manually executing the Python function. The Blob Trigger automatically invokes it when a new blob is uploaded.


## **2. What will the final result look like?**

Suppose you upload:

`AWS-Tutorial.pdf`

The Azure Function will automatically generate:

`AWS-Tutorial.pdf.metadata.json`

Example JSON:

```
{
  "file_name": "AWS-Tutorial.pdf",
  "file_extension": ".pdf",
  "file_type": "application/pdf",
  "file_size_bytes": 204800,
  "file_size_kb": 200.0,
  "source_blob": "uploads/AWS-Tutorial.pdf"
}
```

We will see the original PDF in the first storage account and the generated JSON in the second storage account.

## **3. What Azure resources do we need?**

For a better understanding, we are using two Storage Accounts.

| Azure resource    | Name (example)              | Purpose                 |
| ----------------- | --------------------------- | ----------------------- |
| Storage Account 1 | `stdevopsupload01`          | Stores uploaded files   |
| Storage Account 2 | `stdevopsprocess01`         | Stores JSON metadata    |
| Container 1       | `uploads`                   | Receives original files |
| Container 2       | `file-metadata`             | Receives generated JSON |
| Function App      | `func-devops-fileprocessor` | Executes Python code    |

All storage account names must be globally unique, lowercase, and 3–24 characters. Adjust the example names if unavailable.

The second Storage Account will also be used as the Function App's host storage for this beginner lab. This keeps the architecture simple. In production, consider separating the Function App's host storage from application output storage.

## **4. Create the Azure Storage Accounts**

Open [Azure Portal](https://portal.azure.com/?utm_source=chatgpt.com).

### **Step 1 — Create the first Storage Account**

Search for **Storage accounts → Create**.

Use these settings:

- Resource group: `rg-azure-function-demo`
- Storage account name: `stdevopsupload01` (or a unique name)
- Region: Same region for all demo resources
- Performance: Standard
- Redundancy: Locally-redundant storage (LRS)

Click Review + Create.

### **Step 2 — Create the second Storage Account**

Repeat the process with:

- Resource group: `rg-azure-function-demo`
- Storage account name: `stdevopsprocess01` (or a unique name)
- Performance: Standard
- Redundancy: LRS

### **Step 3 — Create containers**

Open the first Storage Account.

1. Select **Data storage → Containers**.
2. Click **+ Container**.
3. Name it `uploads`.
4. Keep Public access level as **Private (no anonymous access)**.
5. Click Create.

Now open the second Storage Account and create:

`file-metadata`

## **5. Collect the Storage Account connection strings**

Our Python function needs permission to access both Storage Accounts.

For each Storage Account:

1. Open the Storage Account.
2. Select **Security + networking → Access keys**.
3. Click Show.
4. Copy the Connection string under key1.

Keep these two values safe:

- Source connection string: first Storage Account.
- Destination connection string: second Storage Account.

## **6. Create the Azure Function App**
**Python 3.11 + Azure Functions Runtime 4**

Python v2 programming model using decorators

Why Python?

- Easy to understand for beginners.
- Short code.
- Excellent for automation.
- Useful for DevOps engineers.
- Supports Azure SDK libraries.

Microsoft recommends the Python v2 programming model for new applications.&#x20;

### **Create it in Azure Portal**

Search for **Function App → Create**.

Use these settings:

| Setting           | Value                                                      |
| ----------------- | ---------------------------------------------------------- |
| Resource group    | `rg-azure-function-demo`                                   |
| Function App name | `func-devops-fileprocessor`                                |
| Publish           | Code                                                       |
| Runtime stack     | Python                                                     |
| Version           | 3.11, if available                                         |
| Operating system  | Linux                                                      |
| Region            | Same as Storage Accounts                                   |
| Hosting plan      | Consumption or Flex Consumption, depending on availability |

For the storage account used by the Function App, select your second Storage Account: `stdevopsprocess01`.

If the wizard requires a new storage account or does not offer your selected account, create/select the appropriate supported host storage account and use its connection string for `AzureWebJobsStorage`.

Click Review + Create.
